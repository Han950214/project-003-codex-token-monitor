# Phase 3.0 产品交互

Codex Token Monitor 的当前定位是“Codex 工作流状态助手”，不是要求普通用户研究 Token 字段的数据面板。首次启动会自动检测 Codex、读取安全数字、选择最近活动 Thread、获取额度并生成一个最高优先级建议；失败时只在普通视图显示“连接异常 / 一键诊断”。

## 应用外壳

主窗口只有五个一级入口：状态中心、当前任务、历史记录、工具、设置。左下角显示数据连接状态、版本和当前 Dashboard 模式。页面切换只改变可见 Frame，不调用 Rollout、SQLite、标题或额度接口。

状态中心上方提供 `simple` / `advanced` 切换，默认 `simple`。切换立即保存并使用当前内存 snapshot，不改变选中 Thread、历史页码、自动刷新状态或启动模式。

## 极简模式

首页固定为四个主要区域：

1. 当前状态卡：一个结论、最多三行原因、一个主操作和“查看原因”次操作。
2. 额度卡：只展示 5 小时与每周的可靠剩余比例和可靠重置时间；未知值为 `—`。
3. 当前任务卡：安全标题、状态、轮次、本轮用量、会话累计和最近活动；点击进入当前任务页。
4. 快捷操作：一键诊断、打开 Codex、查看历史；“更多”进入工具页。

## 高级模式

高级模式保留专业数字：Input、Output、Total、Cached、Reasoning 和 Cache Hit；Cache Hit 始终说明为本地数字推导，不称为官方值。会话累计、当前任务、数据源、近期会话和遥测仍可见；7/30/90 天、每页 10 条、分页、固定选择、自动跟随和选中高亮位于历史记录页。

历史选择和分页优先使用完整刷新留下的进程内数据。只有目标 Thread 不在缓存或用户显式刷新时才进入既有读取路径。

## 数据访问合同

- 允许访问真实数据：首次自动刷新、手动刷新、固定 60 秒自动刷新、一键诊断。
- 不访问真实数据：导航、语言、Dashboard 模式、组件模式、展开/收起、恢复窗口、设置保存、历史页内翻页和缓存选择。
- UI 页面不直接访问 SQLite 或 Rollout；`DashboardViewModel` 与诊断服务分别提供共享刷新和只读检查路径。
- 进程只有一个 Tk root 和一个 `mainloop`；桌面组件与对话框均为 `CTkToplevel`。

## 中英文

全部新增操作、建议、诊断状态和设置通过集中翻译键生成。内部状态代码和 DTO 字段保持英文，但不直接展示给普通用户。切换语言只重绘当前内存 presentation。
