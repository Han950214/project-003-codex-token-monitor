# Token Monitor UI 原型

原型只回答一个展示决策，不作为生产实现。

## 流程

1. 写明要验证的问题，例如“当前响应与线程累计如何避免混淆”。
2. 使用当前 Python Desktop、CustomTkinter/Tkinter 组件与 presenter 输出，准备两至三套结构明显不同的方案。
3. 使用覆盖单条响应、线程累计、时间范围、额度、未知和过期状态的真实形状数据。
4. 将原型放在明确标记的临时位置，与正式 Dashboard、系统托盘和刷新入口隔离；默认只读，不接入真实数据写入。
5. 比较信息层级、误读风险、窗口缩放、DPI、长数字和异常状态。
6. 方向选定后，将结论落实到正式实现，并删除未采用方案和原型入口。

## 边界

- 最多两至三套；不创建 Git 分支，不自动 commit，不接入正式入口。
- 不修改 usage 解析、Rollout、SQLite、日志读取、归并、额度或数据口径。
- 不迁移技术栈，不新增依赖；用户已有批准参考图时直接进入参考图实现。
- 不执行 push、reset、clean、rebase 或 amend。
